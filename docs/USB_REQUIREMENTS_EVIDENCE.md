## Interpretation audit

- The initial question could mean an ordinary Arch live installer versus an
  installed Jstack desktop. The later clarification establishes a single-USB,
  no-existing-OS workflow. Current README, USB guide, image guide, and on-image
  instructions now describe that workflow directly, without requiring Ubuntu.
- The USB initially lacked Jstack/Niri. The new image includes both live and
  installed Niri, and the separately authorized flash/readbacks now establish
  that this image is on the physical stick. Repository or image-build changes
  alone were not treated as evidence of a changed USB.
- A blank-disk installation was the working interpretation of the OS-less Dell,
  not an observed fact about its disk. No OS does not establish blankness. The
  installer therefore refuses old partitions/signatures. Cleanup is a separate
  decision, not an automatic destructive fallback.
- x86-64 UEFI, Secure Boot disabled with a readable firmware variable, and an
  internal disk of at least 32 GiB are implementation support limits. The disk
  must expose a serial or WWN and kernel disk sequence, with 512-byte or 4096-byte
  logical sectors. The separate Dell's architecture, firmware, disk identity,
  contents, and hardware compatibility have not been observed.
- Offline installation was an implementation choice for the USB workflow, not a
  claim that the user specifically demanded no network. It is now proven with
  no virtual NIC and avoids requiring Ubuntu or package downloads on the target.
- Early private-overlay live-desktop/network evidence was not reused to approve
  the clean installer. The image guide labels it as separate, earlier evidence.
  Clean installation acceptance uses the exact public image identity below.
- The separate Ubuntu recovery installer was not made a prerequisite or used to
  imply rollback guarantees for this Python live installer. No rollback, resume,
  encryption, dual boot, or same-disk recovery guarantee is claimed.
- The old README rule that every ISO file ships in a package conflicted with the
  implemented profile-owned installer/help assets. It is corrected: installed
  desktop defaults are packaged, while live-only assets are generated by the
  versioned profile and removed during conversion.

`/home/jeremy/Downloads/JstackOS-2026-09-06/`.
Paths below are relative to that directory. Full context is in
[USB_INSTALL_ACCEPTANCE.md](USB_INSTALL_ACCEPTANCE.md).

These are not mock installers or substituted source programs. The main and
guided runs boot the actual ISO, execute its installed public commands, write a
new virtual disk with real partition/filesystem tools, and boot that disk without
the ISO. The harness transports input and records observations. Virtual hardware
is nevertheless a substitute for booting the user's physical USB on the Dell.
Software acceptance, physical flash/readback verification, and actual Dell boot
acceptance are therefore reported separately.

previously missing offline installer now completes two real installations, and
